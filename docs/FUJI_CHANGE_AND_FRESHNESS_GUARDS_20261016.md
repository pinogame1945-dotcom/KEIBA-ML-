# 富士ステークス 2026-10-17：発走前の出走変更とソース整合性検証

対象 race_id `202605040611`。本研究のAI推論器・学習済みモデル・凍結L1/L2.1/L3・BACKFILL・MOBILE・mainには変更を加えない。**出走取消・騎手変更の検知と発走前データの照合**だけに限定。

## ① 出走取消・変更の検知

- `scripts/fuji_change_guard_20261016.py` は保存済み2026-10-16 12:18 JST頃の富士S14頭の実出馬表と、netkeibaの公開出馬表を別時点で再取得・照合する。
- 同じ馬IDに対する出走取消（`SCRATCHED`）、除外（`EXCLUDED`）、馬番、枠番、騎手ID、調教師ID、斤量、性齢、馬体重・増減の変化、および馬の追加・削除を検出。**競走中止（DNF）や事後着順と混同しない。**
- **差分があれば**`status=INVALIDATE_RECOMPUTE_REQUIRED`、`prediction_invalidated=true`。CLI終了コードは**2**として後段で古い予測を使わせない。元AIの再計算・バックフィル収集・出馬表変更は自動では実施しない。
- 変更時にHTMLの取得/パースができない場合も`BLOCKED_SOURCE_UNVERIFIED`、exit2で停止。取消しで行そのものが消えた場合も旧馬IDの脱落として検出する。
- **実証結果**：2026-10-16 JST14:27前後時点、当日出走候補は14頭全員が一致。変更0件、取消・除外0件。モックの取消・除外・騎手変更・馬追加/除去・調教師変更・斤量/体重変更・重複/別レース等とCLI fail-closed確認の **12テスト成功**。
- [最終実行：変更検知12テスト＋現在の実富士S出馬表再取得](https://github.com/pinogame1945-dotcom/KEIBA-ML-/actions/runs/38856158108)。

## ② 鮮度・取得元・レース／馬番号の整合性

- `scripts/fuji_integrity_guard_20261016.py` はnetkeiba富士S実ページとJRA公式の同一2026-10-17東京11R出馬表を、それぞれ**新しく取得**。馬名・馬番・枠番・取消／除外状態を全馬について突合する。
- 各リクエストについてrace_id、実際のsource URL host、HTMLのSHA-256、タイムゾーンつきクライアント取得時刻を要求。未来時刻・期限切れ・異なる取得元の時刻差、頭数/馬番の不一致は**BLOCKED**。
- 実測では両公式・民間ページの14頭一致、取消0件、レースID一致、クロスソースエラー0。**11テスト成功**（古い情報・別レース・異時刻・JRA相違・オッズ代用禁止など）。
- CIのテストで使用した `--max-age-seconds 180` と `--max-skew-seconds 120` は**今回の実測用閾値**。モデル/研究/運用の正式な時間鮮度仕様を勝手に定めたものではない。運用に接続する場合は呼び出し側で明示が必須、未設定ならBLOCKED。
- **取得時刻は公開元のデータ更新時刻と同義ではない**。本監査は2ソースをいつクライアントが取得したかを照合している。JRA側の掲載更新時刻は存在を確認できないので捏造しない。
- 非FINALの**実発売オッズはまだ発表前**のため、`CARD_CROSSCHECKED_WAITING_FOR_LIVE_ODDS` とし、買い目判定用の市場情報が揃ったとは扱わない。オッズが与えられる場合は先行作業P4のJRA真正オッズ入力検証器を呼び、公式元と組合せ／取得時刻を検証し、取消馬が含まれる券を拒否する。
- [JRA×netkeibaの実出馬表＋鮮度検証11テスト](https://github.com/pinogame1945-dotcom/KEIBA-ML-/actions/runs/38856026228)。
