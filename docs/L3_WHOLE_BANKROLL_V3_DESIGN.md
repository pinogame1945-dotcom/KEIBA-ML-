# L3 V3 — 全体回収率 × 資金残高 × 枯渇耐性の一括研究

## 目的
L2.1で固定した**全13,479枚・6,877レース**は変更しない。予測順位・軸・馬券の集合・賭け金候補を再最適化せず、V2で予め生成した**26通りの固定賭け金台帳**を、そのまま実際の銀行口座のように決済順で流す。これによって以下を全体ポートフォリオで一度に確認する：

- 1) 全体ROIおよび総利益（均等200円と同額で公平比較）。
- 2) 各開催日の全馬券購入資金を**当日払戻前**に用意するのに必要な**最小初期資金**。
- 3) 初期資金1万 / 2万 / 3万 / 5万 / 10万 / 20万 / 30万 / 50万円で、どの日時に`INSUFFICIENT_BUDGET`になるか。足りない場合は**全券の同一購入継続不可**と明示し、都合よく間引かない。
- 4) 大穴払戻10件を失った場合の回収率、払戻一律0～25%減額という単純な**配当悪化ストレス**。
- 5) 日単位の再標本化1,000回による必要初期資金95・99パーセンタイル、途中資金不足率、ROI差異の参考区間。**未来の確率を示す予測ではない。**

ここではお前が重視している**総体の回収率**を主指標とし、個別券種や人気・オッズの黒字帯に新条件を生み出さない。

## 重要な定義と制限
- 入力は `research-results/l3-global-portfolio-v2/run-38717294078/full_portfolio_stakes.csv.gz` の保存済み全券×政策のステーク。既存の実証済みV2正本を再使用し、馬券を再抽出しない。
- 過去レースの日付ごとに投資額を合計。当該日開始時点にその日の購入総額以上の現金がある場合だけ全レースを実施し、**払戻金を同日末にまとめて入金**する。これは全買い目の資金を日初に確保する安全側の会計であり、当日複数レースの締切・払戻順序を過剰に仮定しない。
- 各政策の固定リストが同一の13,479枚であること、同じ合計投資額であることを検証。FLAT100は正本再現のため半額の参考比較。
- 口座がその日の全購入額を賄えない場合、その日以降の全件購入シミュレーションを止める。途中の券を隠して買わない・軸を変更しない・資金借入や追加入金を勝手に許すことはしない。予算不足モデルを新しい買い方の勝率として計算しない。
- 最低初期資金の算出: `C_min = max_{各日}(その日の購入総額 - 前日までの累積確定損益)`。歴史上の利益で後年の購入原資を賄うことは許すが、**未来の払戻を前倒しすることはしない**。
- 再標本化は過去322開催日からの重複抽出。市場、年度、レース選択の独立性を保証せず、将来確率に直接当てはめてはならない。
- 歴史的`FINAL`オッズは購入締切前の注文可能な価格とは異なる。仮定の払戻減額は感度試験であり、JRAの実際の発券挙動・返還・締切オッズのモデルではない。
- 2023〜2025年の後知恵で選定したL2.1そのものの真のOOSリターンは未証明。2026年の未知年封印を厳守。
- 掛け金拡張、レースの見送り、買い目の削除、実予算に応じた購入点数の変更をしない。運用開始・実発券もしない。

## 生成ファイル
- `global_capital_and_risk.csv`: 26政策の全体ROI、同額総利益、最低初期資金、日末DD、過去黒字年数、上位10件依存、原資効率。
- `annual_capital_and_risk.csv`: 年度別最低必要資金・年度ROI（1年の初日の所持金を新たに0から想定して計算）。
- `bankroll_feasibility_all_policies.csv`: 固定初期資金別に完全購入を維持できたか、資金不足の最初の日付・必要額。
- `hypothetical_payout_haircut_stress.csv`: 歴史的払戻減額に対する総ROI・損益感度。
- `day_bootstrap_capital_and_roi_sensitivity.csv`: 日抽出の参考分布と資金存続率。
- `summary.json`: 不変条件・研究限界・主要候補の集約。

GitHub Actions無料 `ubuntu-latest` 標準CPU、Python標準ライブラリのみで実行。追加データダウンロードなし、GPU、有料runner、Artifact/Cache追加保存なし。専用研究ブランチ以外は一切変更しない。

## 結果の判断
最大ROIを出した政策を単純に本採用しない。**(a) 13,479点全体の同額回収率、(b) 必要初期資金と不足リスク、(c) 上位払戻依存、(d) 事後オッズ価格悪化での採算性、(e) 年間の頑健性**をまとめて確認する。後知恵期間だけを使った研究だから、順位付けは「研究候補」として扱い、実運用に進むには封印データ以外の将来時点固定検証が必要。
