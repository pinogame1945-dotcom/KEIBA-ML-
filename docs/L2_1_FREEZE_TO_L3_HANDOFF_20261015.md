## 5. L3が守る入出力契約

**入力：** L2.1が一意に確定した物理馬券群（`race_date / race_id / bet_type / canonical_selection / source_line_gates / timestamped_ticket_odds / baseline_stake=100`）と、馬券ごとに任意のL1.75信頼度診断（不足は`UNKNOWN`、推測で埋めない）、ユーザー予算・下限・リスク上限。

**出力：** 同一の物理馬券キーに対し、`L2_1_ticket_id, stake_yen, risk_reason, odds_timestamp, portfolio_total_yen`。購入点数・買い目・軸・順位・券種・ゲートを変更しない。

**禁止：**
- 2023–25で儲かった`Q4`などをそのまま最適掛け金として学習済み・未知年保証済みと扱う。
- 信頼度不足や低期待値を理由に隠れて馬券を`0円`・見送りとする。
- 同じ馬券が複数の50ルールに一致したという理由で多重計上する。
- 1頭の`p3`を馬連/三連複/三連単の真の的中確率に転用する。
- 事後確定オッズを買付時点で観測できたかのように扱う。

**予算不足：** 100円単位の全件購入が不可能なら `INSUFFICIENT_BUDGET` を明示し、黙って間引かない。L3で部分購入の新方針を作る場合はL2.1とは独立した別方針・別評価として扱う。

**L3比較の推奨基準：** 全馬券100円固定を必ずベンチマークに据え、信頼度重視・価格重視・両者統合・同一レース集中抑制を同じ買い目で比較。利益・ROI・最大ドローダウン・年度別成績・レース間分散・上位的中依存を全て報告し、2026封印は維持する。

## 6. データ／ダウンロード／実行費用

- Kaggle Datasetを読む必要が生じたら、**metadata/file一覧 → 実在名解決 → 1回だけDL → 同一runnerで再利用**。manifestの正式名を尊重し、`jsonl` → `jsonl.gz`の推測404再試行はしない。
- 404は設計/metadata driftとして停止。429、502、503、504、一時通信障害だけを指数バックオフで再試行。
